# The Story Room shelf — the prototype

This is a **design being fitted to become the Story Room's front door**, not a
document about the Story Room. It was built and refined with Sophie over ~15
rounds in August 2026, each round fixing something she caught on her phone. The
next step is to **replace the current shelf in `/storyroom` with this**, and the
point of committing it here is so the chat doing that can see the finished shape
and every decision baked into it.

`prototype-v5.html` is the live artifact (self-contained, data inlined). Open it
in a browser, or see it in the Chats app:
https://imageforge-q125.onrender.com/api/chatfeed/page/JkGqeMkdeeUhMB39gJu0

## What it replaces

`public/scratchpad.html` (generated by `scripts/gen-scratchpad.py`) currently
opens on `#storylist` — a plain list of `.srow` rows, one per pad, with a small
cover, the title and a beat count. That list is what this replaces. Everything
below the shelf — the beat canvas, the popups, the film — stays as it is.

## The shape

**Two levels, never a jump out.** Shelf → story. Back always means one step; an
earlier version bounced her to a different tool and that was wrong. The page
answers `window.__navBack()` and the Chats viewer's back button asks it first
(see `openPage` in `public/chats.html`).

**The shelf** is three category buttons — Personal · Lessons · NDE — styled
exactly like the witch app's shop category chips (`.shop-cat` in `witch.html`):
rounded rectangles, gold border and gold text when active, horizontally
scrollable. Under them, tiles four across:

- a tile is **a real picture from that story**, never an icon or a label
- **portrait 2:3**, matching the art itself — square tiles cropped her art and
  she caught it immediately
- **the name only** underneath; status lines were removed at her ask
- a story that **contains** other things (the NDE set, the lessons) is drawn as
  a stacked deck with a gold count badge, so depth is visible before tapping

**A story view** shows: the voice (players, full width — a 150px player has no
room to scrub), then **one set of pictures with filter buttons above it**. The
filters are style (Watercolor / Pastel / Colored pencil / The lessons look /
Unsorted) *and* source (the pad / the shelf story / whichever chat made them).
Style and source are two slices of the SAME set — an earlier version showed both
as separate grids and every picture appeared twice, which was the single most
confusing thing in the whole build.

**Unsorted means "no prompt was ever filed for this, so I don't know its
style"** — not a fourth style. The page says so in place. Don't quietly rename
it to something that implies knowledge.

**Tapping a picture** opens a lightbox sized to the screen (not the raw file at
full size), showing the label, the `model · quality` caption, and the exact
prompt in two halves — content and style — read from what the chat that made it
filed. Plus ♥ / ✕, which POST to `/api/gallery/assets/vote` against the chat
that owns the image, so a heart here also shows up in that chat's Assets tab.

## Traps, all of them found live on her phone

- **A tap must never start the autoscroll.** The Compare viewer treats a tap on
  anything that isn't a control as "toggle autoscroll". The page opts out by
  carrying an `onclick` attribute on its root — and **any overlay appended to
  `document.body` needs its own**, which is how closing the lightbox was still
  triggering a scroll after the root was fixed.
- **Anything tappable must be a real link or button.** The four Evan version
  rows were `<div>`s: they did nothing, and the tap fell through to the
  autoscroll handler. She reported it as "there's nothing behind those clicks",
  which was exactly right.
- **Thumbnails go through `/api/story/thumb?w=240&url=…`** (or the asset
  record's own `thumb`). A 219-picture story served as raw PNGs is ~200MB.
- **Portrait video**: `aspect-ratio: auto 2/3` — a `<video>` has no aspect until
  metadata loads and lays out square until then.
- **No gradients, no pill-shaped text buttons** (6px radius), per the house
  rules in CLAUDE.md.

## Where the data comes from

`build-assets.js` rebuilds the inlined `AST` blob. Nothing in the prototype
holds content of its own — every picture points at where it already lives:

- **chat Assets tabs** — `GET /api/gallery/assets?chat=…` (label, `prompt`
  caption, `promptStyle`, `promptContent`, `thumb`, `vote`)
- **the shelf stories** — `GET /api/story` (beats, cards, voiceovers, covers)
- **the pads** — `GET /api/scratchpad/pads` and `GET /api/scratchpad/?pad=…`
- **Firebase Storage** directly for the NDE colored-pencil panels, the supercut
  audio and the lesson read-alouds, which no API lists

## What already exists on the server side

Every story on the prototype shelf **already exists as a pad** with its art in
its own inbox (35 of them, seeded August 2026). `GET /api/scratchpad/inbox`
returns a pad's own inbox when it has one (`source:'story'`) and falls back to
the Playground hearts otherwise; `POST /api/scratchpad/inbox` fills it. So the
work is the front door, not the data.

## The open questions — ANSWERED (Sophie, 2026-08-10) and built

1. **The plain shelf stays as a fallback only, linked from NOWHERE.** Her
   words: "you can keep the plain old story room, but it shouldn't link
   anywhere. We use it as a fallback only if this doesn't work." It lives
   behind `?plain=1` on the pad page — no button reaches it.
2. **Tapping a tile goes STRAIGHT TO THE BEAT CANVAS.** She does want a place
   for the finished films "and stuff" eventually — "that might be a button on
   the beat page that we haven't added yet or something" — deliberately not
   built until she asks.
3. **Categories are `category` on the pad doc**, rendered as the fixed
   Personal · Lessons · NDE chips; a story with no tag files under Personal so
   a brand-new one is never invisible. `POST /api/scratchpad/pads/category`
   sets it; `scripts/seed-pad-categories.js` tagged the seeded stories.

The shelf shipped into the live pad page (`scripts/gen-scratchpad.py`, the
`#stories` sheet) — tests in `scripts/test-storyroom-shelf.js`. This folder
stays as the design record.
